# WB-MGE v3 — ручной smoke-тест UI

Высокоуровневая визуальная проверка веб-интерфейса шлюза. Эти тесты **не** проверяют функциональность шлюза (Modbus-трафик, корректность кэша, реальные сетевые подключения и т.п.) — они подтверждают, что веб-интерфейс не сломан совсем: все страницы открываются, все кнопки реагируют, формы принимают ввод, ничего не выкидывает в белый экран.

## Цель

Поймать регрессии уровня «нажимаем кнопку — ничего не происходит», «открываешь страницу — пустота», «верстка разъехалась», «модалка не закрывается», «бургер-меню не открывается».

Если какой-то шаг ниже даёт результат, не описанный в «Ожидание», — это баг.

## Подготовка

1. Тестовое устройство WB-MGE v.3 включено и доступно по IP в той же сети.
2. Логин по умолчанию `admin` / `admin`.
3. Браузер — последний Chrome / Firefox / Safari. Кэш чистый (Ctrl+Shift+R или приватное окно).
4. Тесты выполнять последовательно по разделам. Если шаг ломает состояние устройства — продолжать со следующего раздела, не перезагружая.
5. В конце всего прогона — пройти раздел «Мобильное разрешение» (это обязательное требование).

Все страницы:

| Маршрут | Страница | Группа в меню |
|---------|----------|----------------|

## 1. Страница входа

### 1.1. Открытие

1. Открыть в адресной строке `http://<IP>/`.
2. Должно произойти редирект на `#/login`.

**Ожидание:** загружается экран входа: слева — логотип, заголовок «MGE: Your Swiss Army Knife for Modbus», поля **Username** и **Password**, кнопка **Login** (неактивна), ссылка **Documentation**, выпадашка языка, ссылка `wirenboard.com`. Справа — пустая зелёная декоративная панель. Чип `WB-MGE v3 · <hostname>` под логотипом.

### 1.2. Переключение языка

1. Кликнуть в выпадашку языка внизу формы.
2. Выбрать **Русский**.

**Ожидание:** все надписи (заголовок, описание, кнопка, лейблы) переключаются на русский. Кнопка становится «Войти».

3. Поочерёдно проверить **Қазақша**, **Italiano**, **Deutsch**, потом вернуться в English/Русский.

**Ожидание:** для каждого языка надписи меняются, выпадашка не «зависает», страница не моргает.

### 1.3. Активация кнопки

1. Очистить поле логина.
2. Кнопка **Войти** должна быть disabled.
3. Ввести любой текст в логин и в пароль.

**Ожидание:** кнопка становится активной.

### 1.4. Невалидный логин

1. Логин `wrong`, пароль `wrong` → нажать **Войти**.

**Ожидание:** появляется алерт «Введены неверные логин или пароль». Поля остаются заполненными, кнопка снова активна.

### 1.5. Валидный логин

1. Логин `admin`, пароль `admin` → **Войти**.

**Ожидание:** редирект на `#/`, открывается Dashboard, в левой панели снизу появляется кнопка «Выйти».

### 1.6. Ссылка Documentation

1. На странице логина кликнуть **Documentation**.

**Ожидание:** новая вкладка с wiki Wirenboard.

### 1.7. Прямой доступ к защищённому URL без сессии

1. В инкогнито-окне открыть напрямую `http://<IP>/#/sniffer` (без предварительного логина).

**Ожидание:** автоматический редирект на `#/login`. После успешного входа — редирект на `#/sniffer` (исходный маршрут сохраняется, а не заменяется на `#/`).

## 2. Сайдбар (общая навигация)

Этот раздел проверяется один раз — на любой странице после логина (например, на Dashboard).

### 2.1. Состав меню

**Ожидание:** в сайдбаре сверху вниз:
- Логотип Wiren Board (кликабельный, ведёт на `/`).
- Hostname (например, `WB-MGE-30D7CF`).
- Группа **OVERVIEW** → Dashboard.
- Группа **MODBUS TOOLS** → TCP gateway, Sniffer, Register map.
- Группа **CONFIGURATION** → Network, Serial ports, System.
- Блок **Port 1** / **Port 2** с статусом IDLE/ACTIVE, текущим режимом и параметрами линии (например, `9600 · 8N2`).
- Ссылки Documentation, Support, Buy devices.
- Кнопка **Logout** снизу.

### 2.2. Активный пункт меню

1. Кликнуть **Sniffer** в меню.

**Ожидание:** строка Sniffer подсвечена зелёной полоской слева, иконка зелёная, страница переключается на сниффер. Адресная строка содержит `#/sniffer`.

### 2.3. Все пункты меню открываются

Поочерёдно кликнуть каждый пункт меню и проверить, что соответствующая страница открывается, заголовок страницы соответствует пункту меню, нет белого экрана / падения JS.

| Пункт | Заголовок страницы |
|-------|--------------------|
| Dashboard | Dashboard / Обзор |
| TCP gateway | TCP gateway / TCP-шлюз |
| Sniffer | Sniffer / Сниффер |
| Register map | Register map / Карта регистров |
| Network | Network / Сеть |
| Serial ports | Serial ports / Последовательные порты |
| System | System / Система |

### 2.4. Внешние ссылки

1. Кликнуть **Documentation** в сайдбаре — открывается новая вкладка с wiki.
2. **Support** — открывается mailto: или ссылка на сайт поддержки.
3. **Buy devices** — открывается `wirenboard.com`.

### 2.5. Кнопка Logout

1. Кликнуть **Logout**.

**Ожидание:** редирект на `#/login`. Если затем перейти на любой защищённый маршрут (например, `#/sniffer`) — снова редирект на логин. Затем войти обратно для продолжения тестов.

### 2.6. Индикация TX Disabled в сайдбаре

*Предусловие:* в Serial ports → Port N → включить **Disable transmission (TX)** и сохранить настройки.

**Ожидание:** в блоке **Port N** в строке «Line» сайдбара рядом с параметрами линии (например, `9600 · 8N1`) появляется «· ~~TX~~» — зачёркнутое красным цветом «TX».

*После проверки вернуть Disable TX в исходное положение и сохранить.*

## 3. Dashboard

### 3.1. Открытие

1. Перейти на `#/`.

**Ожидание:** заголовок «Dashboard» + крошки «Gateway overview». Две колонки карточек:
- Левая: **Ethernet**, **Wi-Fi**, **Gateway**.
- Правая: **RS-485 · Port 1**, **RS-485 · Port 2**.

Все карточки заполнены данными (IP, MAC, версия прошивки, напряжение питания, uptime, режим/параметры RS-485). В пустых значениях вместо `null` стоит `—`.

### 3.2. Бейджи статусов

В шапке каждой карточки видны разноцветные «таблетки»:
- Ethernet: `Connected` (зелёная) или `Not connected` (серая).
- Wi-Fi: `Enabled` / `Disabled`.
- RS-485: `Active` / `Inactive`.

**Ожидание:** цвета и текст соответствуют статусу.

### 3.3. Кнопки-шестерёнки → переход в настройки

1. Кликнуть шестерёнку в шапке карточки **Ethernet** — переход на `#/network`.
2. Вернуться. Кликнуть шестерёнку в **Wi-Fi** — также `#/network`.
3. Шестерёнка **RS-485 · Port 1** — переход на `#/settings`.
4. Шестерёнка **RS-485 · Port 2** — переход на `#/settings`.

**Ожидание:** каждая шестерёнка работает и ведёт в нужный раздел.

### 3.4. Версия прошивки

1. Найти карточку **Gateway** → строка «Firmware».

**Ожидание:** показана текущая версия. Если устройство имеет доступ в интернет — справа подпись `(up to date)` или `(latest <X.Y.Z>)` плюс кнопка **Update**. Если интернета нет — просто номер версии без падений.

### 3.5. Кнопка Update (если есть)

1. Если рядом с версией есть кнопка **Update** — кликнуть её.

**Ожидание:** редирект на `#/system`.

### 3.6. Карточка Wi-Fi — режим STA (клиент)

*Выполнять, если устройство подключено к Wi-Fi в режиме клиента.*

**Ожидание:** в карточке **Wi-Fi** отображаются строки:
- **Connection**: «Connected» или «Not connected».
- **SSID**: имя сети (если подключено).
- **IP address**, **MAC address**.
- **RSSI** в dBm (если подключено).

Значения не пустые и не `null`.

### 3.7. Карточка Wi-Fi — режим AP (точка доступа)

*Выполнять, если устройство работает как точка доступа.*

**Ожидание:** в карточке **Wi-Fi** отображаются строки:
- **Number of connections** (количество подключённых клиентов).
- **IP address** (адрес AP), **MAC address** (MAC AP).

RSSI и SSID подключения не отображаются.

## 4. TCP-шлюз

### 4.1. Открытие

1. Перейти в **TCP gateway**.

**Ожидание:** заголовок «TCP gateway», две карточки: «RS-485 · Port 1» и «RS-485 · Port 2». В каждой — селект **Mode**, селект **Bridge mode**, поле **Port** (number input). Кнопка **Save** — disabled.

### 4.2. Переключение режима Modbus

1. В карточке Port 1 переключить **Mode** → `Modbus TCP`.

**Ожидание:** поле **Bridge mode** исчезает (оно нужно только для transparent bridge). Кнопка **Save** становится активной.

2. Переключить обратно → `Transparent bridge`.

**Ожидание:** поле **Bridge mode** появляется снова.

### 4.3. Переключение Bridge mode (Server/Client)

1. **Bridge mode** → `Client`.

**Ожидание:** появляется дополнительное поле **IP address** для адреса удалённого сервера. Кнопка **Save** — активна.

2. **Bridge mode** → `Server`.

**Ожидание:** поле **IP address** исчезает.

### 4.4. Поле Port (числовое поле)

1. Ввести в **Port** значение `0` или `100000` — за пределами диапазона 1–65535.

**Ожидание:** поле подсвечивает невалидность (нативная подсказка браузера или красная рамка), кнопка **Save** не позволяет сохранить.

2. Установить порту Port 1 такое же значение, как у Port 2 (по умолчанию 502 и 503).

**Ожидание:** обе карточки показывают красную подсказку «Port values must be unique» / «Значение порта должно быть уникальным», обе **Save** disabled.

3. Вернуть уникальные значения — подсказка исчезает.

### 4.5. Save (не нажимать, если устройство в проде)

> ⚠️ Сохранение реально меняет конфигурацию шлюза. На тестовом стенде безопасно — нажать **Save** в Port 1 после любого валидного изменения.

**Ожидание:** кнопка показывает состояние загрузки и становится disabled. Через ~1 с — успех, кнопка снова disabled (изменений нет). Перезагрузка страницы возвращает то же значение (изменение применилось).

## 5. Сниффер

### 5.1. Открытие

1. Перейти в **Sniffer**.

**Ожидание:** заголовок «Sniffer». В тулбаре:
- Счётчики `0 packets`, `0 errors`.
- Кнопки выбора порта: **Port 1**, **Port 2** (Port 1 — активна по умолчанию).
- Кнопка **Start** (зелёная).
- Кнопка **▶ Send packet** (outline).
- Кнопка **Clear** (outline).
- Кнопка **Export CSV** (disabled, пока пакетов 0).

Слева — фасетный рейл со **Slave ID** и **Function code** (оба «0 seen · all selected»). Справа — пустая таблица с колонками `# / Time / Δt / Sender / Slave / Function / Payload / Bytes / CRC`.

### 5.2. Переключение порта

1. Кликнуть **Port 2** в тулбаре.

**Ожидание:** Port 2 становится активным (визуально), Port 1 — неактивным. Никакой ошибки.

2. Вернуться на Port 1.

### 5.3. Start / Stop

1. Нажать **Start**.

**Ожидание:** кнопка моментально становится красной **Stop**. Если по шине идёт реальный Modbus-трафик — в таблице появляются строки, иначе остаётся пустой (это допустимо для смоук-теста). Никакого зависания UI.

2. Нажать **Stop**.

**Ожидание:** кнопка возвращается в **Start** (зелёная). Захват прекращается.

### 5.4. Двойной клик Start

1. Кликнуть **Start** дважды подряд (быстро).

**Ожидание:** UI не виснет, кнопка корректно отрабатывает: один клик — Start, второй — Stop. (Подробнее этот сценарий описан в `sniffer_cache_bug_test.md`.)

### 5.5. Clear

1. Если в таблице есть строки — нажать **Clear**.

**Ожидание:** таблица очищается, счётчики становятся `0 packets`. Фасеты также сбрасываются.

### 5.6. Export CSV

1. Если в таблице есть строки — нажать **Export CSV**.

**Ожидание:** браузер скачивает файл `sniffer_port<N>.csv`. Если пакетов нет — кнопка disabled.

### 5.7. Попап отправки пакета

1. Нажать **▶ Send packet**.

**Ожидание:** открывается всплывающее окно с формой: Slave ID, Function code, Start address, Value/Quantity, сегментный переключатель **Read / Write**. Видно превью кадра в HEX.

2. Изменить любое поле — превью обновляется.

3. Переключить сегментный контрол с **Read** на **Write**.

**Ожидание:** список Function code меняется (FC01–FC04 → FC05/FC06/FC15/FC16), лейбл четвёртого поля меняется с «Count» на «Value», превью кадра обновляется.

4. Ввести заведомо некорректный Slave ID (`0` или `256`).

**Ожидание:** превью кадра показывает `—`, кнопка отправки disabled.

5. Закрыть попап (крестик или клик вне попапа).

**Ожидание:** попап исчезает без ошибок.

6. Не останавливая захват (кнопка **Stop** не нажата), открыть попап **▶ Send packet** снова.

**Ожидание:** попап открывается поверх таблицы. Захват продолжается (строки добавляются в таблицу за попапом). Нет визуального сбоя, нет закрытия попапа при поступлении нового пакета.

> Сам факт реальной отправки пакета по шине — это уже не smoke-тест, его проверять не обязательно.

Если по выбранному порту в настройках включён **Disable TX** — кнопка **Send packet** должна быть **disabled**.

### 5.8. Фасеты Slave ID / Function code

Эти контролы видны, только если есть пакеты. Если пакеты есть:

1. Кликнуть на строку в Slave ID.

**Ожидание:** строка отмечается галкой, в таблице видны только пакеты этого слейва. Счётчик в шапке фасета меняется на `N selected`.

2. Кликнуть **clear** в шапке фасета — фильтр сбрасывается.

Аналогично для **Function code**.

### 5.9. Декодер пакета

1. Кликнуть на любую строку в таблице (если есть пакеты).

**Ожидание:** строка подсвечивается, ниже / справа появляется панель с разбором байтов (адрес, функция, payload, CRC).

### 5.10. Счётчик ошибок CRC

*Выполнять только при наличии трафика с повреждёнными пакетами на шине.*

**Ожидание:** счётчик `N errors` в тулбаре увеличивается при поступлении пакетов с неверным CRC. После нажатия **Clear** — сбрасывается в `0 errors`.

## 6. Карта регистров

### 6.1. Открытие при выключенном кэше

1. Перейти в **Register map** (после сброса устройства или если кэш не включался).

**Ожидание:** заголовок «Register map». В шапке тогглер `CACHING OFF`. В теле — большая плашка с иконкой сетки, текстом «Register map caching is disabled» и кнопкой **Enable caching**. В правой панели Settings видны кнопки портов: **Port 1** должна быть **активна** (подсвечена), **Port 2** — неактивна. Это состояние по умолчанию — порт 1 предвыбран даже до включения кэша. Если обе иконки неактивны — это регрессия.

### 6.2. Включение кэша через кнопку

1. Нажать **Enable caching**.

**Ожидание:** тогглер переключается в `CACHING ON`. Большая плашка исчезает, появляется спиннер «Loading…» и затем таблица устройств. В сайдбаре у выбранного порта режим становится **Cache bus**.

### 6.3. Выключение кэша через тогглер

1. Кликнуть тогглер `CACHING ON` в шапке.

**Ожидание:** возвращается состояние «Caching disabled». В сайдбаре у порта возвращается режим **Disabled**.

### 6.4. Панель Settings (когда кэш включён)

При включённом кэше в правой части страницы видна панель с настройками:
- Радиокнопки **Port 1** / **Port 2** (выбор активного порта-источника).
- Поле **TCP server port** (порт Modbus TCP-сервера, по умолчанию 504).
- Тогглер включения TCP-сервера.
- Поле **Value timeout (s)**.
- Кнопка **Save**.

1. Переключить радио с Port 1 на Port 2.

**Ожидание:** радио переключается, кнопка **Save** активна.

2. Нажать **Save**.

**Ожидание:** надпись «Saving…», затем «Saved» (зелёная) → через 3 с скрывается. Порт реально переключается (см. сайдбар).

### 6.7. Переключение активного порта-источника и перезагрузка таблицы

*Выполнять при наличии устройств в кэше хотя бы на одном из портов.*

1. При включённом кэше на Port 1 переключить радио на **Port 2** и нажать **Save**.

**Ожидание:** сайдбар показывает «Cache bus» у Port 2 вместо Port 1. Таблица устройств перезагружается и отражает данные Port 2 (или пустое состояние, если на Port 2 нет устройств). Нет зависания, нет белого экрана.

### 6.5. Поиск, expand/collapse

При наличии устройств в таблице:

1. Ввести в строку поиска `1` или часть hex-адреса.

**Ожидание:** таблица фильтруется. Если совпадений нет — пустое состояние без падений.

2. Нажать **Expand all** / **Collapse all** (если такие кнопки есть в шапке таблицы).

**Ожидание:** все строки раскрываются / сворачиваются.

### 6.6. Export

1. Нажать **Export JSON** (или кнопку загрузки JSON).

**Ожидание:** браузер скачивает `register-map-<timestamp>.json`. Файл — валидный JSON.

## 7. Сеть

### 7.1. Открытие

1. Перейти в **Network**.

**Ожидание:** заголовок «Network». Две карточки: **Ethernet** и **Wi-Fi**. Обе **Save** — disabled.

### 7.2. Ethernet — DHCP

1. Снять чекбокс **DHCP client** (тогглер).

**Ожидание:** появляются три поля: **IP**, **Gateway**, **Mask**. Кнопка **Save** активна.

2. Ввести в IP невалидное значение (например, `999.999.999.999`).

**Ожидание:** поле подсвечивает невалидность.

3. Включить **DHCP client** обратно.

**Ожидание:** поля исчезают. Save снова disabled (если других изменений нет).

### 7.3. Wi-Fi — режим

1. В выпадашке **Mode** переключить на **Disabled**.

**Ожидание:** все поля Wi-Fi скрываются. Save активна.

2. Переключить на **Client (sta)**.

**Ожидание:** появляются поля для подключения к сети (SSID-селект, защита, пароль, DHCP-клиент, опционально статический IP).

3. Кликнуть селект SSID (с иконкой Reload).

**Ожидание:** запускается сканирование, появляются доступные сети. Не падает, даже если сетей нет.

4. Кликнуть Reload-иконку рядом — повторное сканирование.

5. Ввести вручную SSID, которого нет в списке.

**Ожидание:** имя добавляется в список и выбирается.

6. Переключить **Mode** обратно на **Access Point (ap)**.

**Ожидание:** поля для AP: SSID, защита (Open/WPA2/WPA3), пароль, статический IP, маска, шлюз.

7. В защите выбрать **Open** — поле пароля скрывается. Выбрать WPA2 — поле возвращается с placeholder.

8. Ввести SSID длиннее 32 символов или с не-ASCII символами.

**Ожидание:** валидация показывает подсказку, Save запрещает сохранение.

9. Установить защиту **WPA2**, ввести пароль, затем переключить на **Open** и обратно на **WPA2**.

**Ожидание:** при возврате на WPA2 поле пароля пустое (или заполнено прежним значением). Поле не содержит мусора, кнопка **Save** активна.

### 7.4. Wi-Fi полностью отключён (только если устройство такое поддерживает)

Если в прошивке `wifi_perm_disable=true` — карточки Wi-Fi не должно быть вовсе, только Ethernet.

## 9. Система

### 9.1. Открытие

1. Перейти в **System**.

**Ожидание:** заголовок «System». В двух колонках карточки:
- Левая: **Device name**, **Device information**, **Power**.
- Правая: **Web interface**, **Firmware**, **Reboot**, **Configuration**.

### 9.2. Device name

1. Изменить значение поля **Name**.

**Ожидание:** Save становится активной. Под полем — ссылка `http://<name>.local`.

2. Очистить поле.

**Ожидание:** Save — disabled.

### 9.3. Device information

**Ожидание:** видны serial number, uptime, heap memory (`used(hwm)/all KB`), статус PSRAM. Значения не пустые / не `null`.

### 9.4. Power Vout

1. Кликнуть тогглер `Vout` в шапке карточки **Power**.

**Ожидание:** тогглер сразу меняет состояние и сохраняется автоматически (без отдельной кнопки Save).

### 9.5. Web interface

1. Изменить **Port** (например, 80 → 8080).

**Ожидание:** Save активна.

2. Изменить **Username**, **Password**.

**Ожидание:** Save активна, никаких падений при наборе текста.

4. Ввести в **Username** недопустимый символ (например, `admin@host` или `admin имя`).

**Ожидание:** поле подсвечивает ошибку, браузер показывает подсказку «Use only Latin letters, numbers, hyphens, and underscores» (или локализованный аналог). Кнопка **Save** недоступна.

5. Ввести в **Password** символ вне диапазона printable ASCII (например, вставить Unicode-эмодзи).

**Ожидание:** аналогичная inline-подсказка «Use only Latin letters, numbers, spaces, and special characters».

3. Поменять язык через выпадашку.

**Ожидание:** язык всего UI меняется немедленно. Save становится активной (если язык отличается от сохранённого).

> ⚠️ Сохранение изменит порт/логин/пароль реально. Будьте готовы зайти заново.

### 9.6. Firmware

**Ожидание:** показана текущая версия и (если есть интернет) последняя доступная в скобках.

1. Кликнуть **Choose file** под «Install from file».

**Ожидание:** открывается диалог выбора файла. (Реально файл не загружать, если нет необходимости.)

2. Если рядом с версией видна кнопка **Download X.Y.Z** — кликнуть её.

**Ожидание:** скачивается новая прошивка файлом.

### 9.7. Reboot

1. Запомнить текущее значение **Uptime** в карточке «Device information».

2. Нажать **Reboot device**.

**Ожидание:** появляется браузерный confirm. **Cancel** — ничего не происходит. **OK** — устройство уходит в перезагрузку, UI блокируется и сам перезагружается через ~3.5 с. После возвращения страницы значение **Uptime** сбрасывается до 0 минут (гораздо меньше, чем было до перезагрузки).

> ⚠️ Перезагрузка реальная. Выполнять только если можно временно потерять связь.

### 9.8. Configuration: Export / Import

1. Нажать **Download settings**.

**Ожидание:** браузер скачивает файл с конфигом (JSON или подобный).

2. Нажать **Upload settings**.

**Ожидание:** открывается диалог выбора файла. (Реально не загружать без необходимости.)

### 9.9. Factory reset

1. Запомнить текущее значение **Device name** (hostname) из карточки «Device name» (например, `WB-MGE-30D7CF`) и baud rate Port 1 из сайдбара.

2. Изменить **Device name** на произвольное (например, `test-device`) и нажать **Save** в карточке. Убедиться, что изменение применилось (hostname виден в сайдбаре и в ссылке `http://test-device.local`).

3. Нажать **Factory reset**.

**Ожидание:** появляется confirm с предупреждением. **Cancel** — ничего не происходит, Device name остаётся `test-device`.

> ⚠️ **OK не нажимать** — это уничтожит конфигурацию устройства. В смоук-тесте проверяем только сам факт открытия confirm-диалога.

> Если тест проводится в рамках полного прогона с реальным сбросом: нажать **OK** → дождаться перезагрузки → убедиться, что hostname вернулся к заводскому (вида `WB-MGE-XXXXXX`), а baud rate Port 1 снова равен заводскому значению (9600). Это подтверждает, что Factory reset действительно очищает NVS-настройки, а не просто перезагружает устройство.

## 10. Мобильное разрешение

> **Обязательный раздел.** Одно из требований к UI — корректная работа на мобильных устройствах.

### Подготовка

В DevTools браузера переключиться в Device Mode (мобильный вьюпорт). Рекомендуемые разрешения:
- 360×800 (Android, типовое)
- 390×844 (iPhone 14)
- 768×1024 (iPad mini, на границе)

Граница верстки между мобильным и десктопом — `680px` (см. `Sidebar.vue`, `Login.vue`).

### 10.1. Логин на мобиле

1. На разрешении 390×844 открыть `/#/login`.

**Ожидание:** правая декоративная панель скрыта, форма занимает всю ширину. Текст не выходит за края, поля и кнопка не «разъезжаются». Логотип, чип hostname, заголовок, поля, кнопка, ссылки внизу — все читаемы.

### 10.2. Шапка после входа

После входа на мобильном вьюпорте:

**Ожидание:** сайдбар превращается в горизонтальную шапку высотой ~56px вверху экрана. Слева — лого + hostname, справа — иконка «бургера». Основной контент занимает весь экран ниже шапки.

### 10.3. Бургер-меню

1. Нажать бургер.

**Ожидание:** справа выезжает панель навигации шириной ~240 px, остальная часть экрана затемняется полупрозрачным скримом. Видны все группы меню, список портов, ссылки и Logout.

2. Кликнуть скрим (тёмная область слева от меню).

**Ожидание:** меню закрывается.

3. Снова открыть бургер. Кликнуть любой пункт (например, **Sniffer**).

**Ожидание:** происходит переход на страницу, меню автоматически закрывается.

### 10.4. Все страницы на мобиле

Поочерёдно открыть каждую страницу (через бургер), на каждой проверить:
- Заголовок и крошки видны.
- Карточки занимают всю ширину (одна колонка, не две).
- Кнопки и поля помещаются по ширине, не обрезаются.
- Нет горизонтального скролла страницы.
- Текст не наезжает на иконки/таблетки статусов.

Особое внимание:

| Страница | Что проверить особенно |
|----------|------------------------|
| Dashboard | Все 5 карточек идут в столбик; статусные «таблетки» не залезают на заголовок. |
| TCP gateway | Поля Port помещаются; селекты раскрываются. |
| Sniffer | Тулбар (счётчики, порты, Start, Send/Clear/Export) переносится по строкам, не обрезается. Таблица скроллится горизонтально внутри своего контейнера, а не выбрасывает страницу. Попап Send packet помещается. Фасетный рейл либо переезжает над таблицей, либо корректно скроллится. |
| Register map | Тогглер `CACHING` в шапке не «вылазит». Таблица устройств скроллится. |
| Network | Селект Wi-Fi SSID раскрывается и не выходит за экран. |
| Serial ports | Все три блока (Port 1, Port 2, I/O Bus) идут столбиком. |
| System | Кнопки **Reboot device**, **Factory reset**, **Choose file** — не залезают друг на друга, помещаются на экран. |

### 10.5. Поворот экрана / landscape

1. Развернуть устройство в горизонтальную ориентацию (или эмуляцию `landscape`).

**Ожидание:** если ширина становится > 680 px — сайдбар возвращается в виде боковой панели. Контент не дёргается, перерисовывается чисто.

### 10.6. Скролл и попапы

1. На сниффере (мобильный вьюпорт, 390×844) нажать **▶ Send packet**.

**Ожидание:** попап открывается и помещается на экран (или корректно скроллится внутри себя), его можно закрыть. Нет горизонтального overflow страницы. Форма (Slave ID, FC, Address, Count/Value, превью, кнопка отправки) доступна без зума.

> ⚠️ Известный риск: ширина попапа захардкожена как `480px` при `position: absolute`. На viewport 390 px это может давать горизонтальный overflow — фиксировать как баг верстки.

2. На системе нажать **Reboot device** → **Cancel**.

**Ожидание:** нативный confirm появляется и корректно закрывается.

## 12. Sniffer после цикла кэша

Один из неочевидных сценариев: запустить сниффер после того, как порт побывал в режиме кэша и был оттуда выключен. Полезен, потому что задействует взаимодействие двух страниц — **Register map** и **Sniffer**.

Контекст: когда пользователь выключает кэш на странице Register map, порт переходит в режим `disabled` (а не возвращается в предыдущий режим). Sniffer.vue при старте сам должен переключить порт в `sniffer`.

### Шаги

1. Открыть веб-интерфейс.
2. Перейти в **Register map**.
3. Включить кэширование — нажать тогглер. Порт переходит в режим `cache_bus`.
4. Подождать 2–3 секунды, чтобы кэш стал активным.
5. Выключить кэширование — нажать тогглер ещё раз. Порт переходит в режим `disabled`.
6. Перейти в **Sniffer**.
7. Выбрать порт 1 (или тот, который использовался для кэша).
8. Нажать **Start**.

**Ожидание:** страница автоматически переключает порт в режим `sniffer`, в таблице в течение секунды появляются пакеты (если на шине идёт трафик). Если порт остался в `disabled` и таблица пустая при наличии трафика — это регрессия.

### Как это устроено в коде

`Sniffer.vue:startCapture()` перед подключением WebSocket запрашивает текущий режим порта через `GET /info`. Если порт в режиме, который не может производить данные для сниффинга (`disabled`, `tcp_bridge` или любой другой, кроме `sniffer` и `cache_bus`), — отправляет `POST /ports/N/mode {"mode":"sniffer"}` и ждёт 500 мс, пока прошивка переинициализирует UART, после чего открывает WebSocket.

### Смежные кейсы

#### Сценарий 2: Старт из режима `sniffer` (baseline — должно работать)

1. **Register map** → выключить кэш (порт → `disabled`).
2. Вручную перевести порт в `sniffer` через настройки порта ИЛИ просто нажать Start на странице Sniffer.
3. Нажать **Start**.
4. **Ожидание:** данные появляются сразу.

#### Сценарий 3: Старт при порте в `cache_bus`

1. **Register map** → включить кэш (порт → `cache_bus`).
2. Перейти в **Sniffer**, нажать **Start**.
3. **Ожидание:** сниффер работает параллельно с кэшем (оба режима `sniffer` и `cache_bus` дают пригодные для сниффинга данные). Порт **не** переключается.

#### Сценарий 4: Старт при порте в `tcp_bridge`

1. Убедиться, что порт в режиме `tcp_bridge` (значение по умолчанию после сброса).
2. Перейти в **Sniffer**, нажать **Start**.
3. **Ожидание:** порт **автоматически переключается** в режим `sniffer` (как при `disabled`). В таблице в течение секунды появляются пакеты (если на шине идёт трафик). Если таблица пустая при наличии трафика — это регрессия.

#### Сценарий 5: Двойной клик Start

1. Порт в режиме `disabled` (после выключения кэша).
2. Быстро кликнуть **Start** дважды.
3. **Ожидание:** создаётся только одно WebSocket-соединение. Кнопка превращается в **Stop** сразу после первого клика, поэтому второй клик трактуется как **Stop**, а не как второй **Start**.

#### Сценарий 6: Клик Stop во время процесса Start

1. Порт в `disabled`.
2. Нажать **Start** (запускается переключение режима + 500 мс задержка).
3. Нажать **Stop** до того, как 500 мс истекут.
4. **Ожидание:** WebSocket НЕ подключается, пакеты не появляются. Кнопка возвращается в **Start**.
